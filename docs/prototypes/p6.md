# Prototype 6 — Completed application to verification and acceptance

## Scope

The Release Agent checks verification evidence and opens a pull request that records the result. `deploy_application` requires human approval and then sends no hosting request. `deployed` stays false. Task Tracker Lite is not deployed, because the earlier stages have not produced an approved application.

Tests use `fixtures/test/p6-release/`. That fixture is not a completed application and cannot be recorded as a baseline.

## Acceptance criteria

- Evidence with passing tests, a named implementation baseline, and an unchanged TOR passes verification.
- Missing tests, a changed TOR, or a claim of `Deployed: true` fails.
- A fixture cannot open a release pull request.
- `deployApplication` returns `deployed: false` and an empty request list whether or not a person has approved.
- A Vercel deployment URL is rejected before any request would be sent.

## Slack

Route: `https://wewebplus-software-factory.vercel.app/eve/release/v1/slack`. Same scopes and allowlist. One Slack app has one event URL, so this route needs its own app or a later router. Optional env: `RELEASE_AGENT_MODEL`. No new GitHub permissions. No Vercel deploy token is used.
