# Prototype 2 — Approved SRS to approved architecture

## Scope

The Architecture Agent reads an approved SRS baseline and drafts `docs/architecture.md`. A person reviews that draft in a GitHub pull request. The agent never merges. After a human merge, a follow-up pull request records `architecture.baseline.mergeCommit`.

The frozen TOR and the approved SRS are not rewritten. Fixtures under `fixtures/test/` are labeled test input and cannot become a project baseline.

No approved SRS exists for Task Tracker Lite yet (`srs.status` is `none`). Tests use `fixtures/test/p2-approved-srs/`.

## Acceptance criteria

- A valid architecture with `C-nnn` components, SRS sources, and the SRS sha256 passes validation.
- A missing section, an unknown requirement id, or a component that adds external customer access fails validation.
- A fixture cannot open a project pull request or be recorded as a baseline.
- An unapproved SRS baseline cannot start a project architecture.
- Writes cannot touch `docs/tor.md`, fixtures, or knowledge.
- The pull-request client still rejects merge URLs.
