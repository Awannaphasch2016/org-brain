# Prototype 3 — Approved architecture to feature issues

## Scope

The Planning Agent reads an approved architecture and drafts `docs/feature-issues.md` with dependencies. A person reviews that plan in a pull request. After they merge it, `create_github_issues` opens one GitHub issue per item. The agent never merges.

Task Tracker Lite has no approved architecture. Tests use `fixtures/test/p3-approved-architecture/`. Fixtures cannot open a project pull request or create live issues.

## Acceptance criteria

- A two-issue plan with a valid dependency order passes.
- A dependency cycle fails.
- An unknown component source fails.
- Fixture input cannot create GitHub issues.
- Issue creation uses `POST /issues` and never a merge URL.

## GitHub permission

Creating issues needs the GitHub App **Issues: write** permission in addition to Prototype 1's Metadata read, Contents write, and Pull requests write. The fine-grained PAT needs the same Issues access.

## Slack

Route: `https://wewebplus-software-factory.vercel.app/eve/planning/v1/slack`. Same scopes and allowlist. One Slack app still has one event URL, so this route needs its own app or a later router. Optional env: `PLANNING_AGENT_MODEL`.
