## 2. Project Background and Objectives

### 2.1 Project Background

A small team currently tracks work through informal conversations and manually maintained notes. This makes it difficult to maintain a consistent view of assigned tasks and their progress.

### 2.2 Project Purpose

Create a simple internal web application for recording and tracking team tasks.

### 2.3 Project Objectives

* Allow team members to record work items.
* Allow team members to view relevant tasks.
* Allow authorized users to update task progress.
* Provide a consistent view of task status.

## 3. Project Scope

### 3.1 In Scope

* Create tasks with a title and description.
* Assign tasks to team members.
* View tasks and their current status.
* Update task status.
* Persist task information between sessions.
* Support internal team use.

### 3.2 Out of Scope

* External customer access.
* Payment processing.
* Third-party project-management integrations.
* Advanced analytics.
* Mobile-native applications.

### 3.3 High-Level Requirements

| Group | Requirement |
|---|---|
| Task Management | The system shall support creation, assignment, and tracking of tasks. |
| User Access | The system shall distinguish users and enforce appropriate task permissions. |
| Data | Task information shall persist between sessions. |
| Usability | Users shall be able to view and update relevant task information through a web interface. |

## 4. Deliverables and Acceptance

### 4.1 Software Deliverables

A working internal web application supporting the capabilities defined in scope.

### 4.2 Documentation Deliverables

Software Requirements Specification and subsequent technical documentation appropriate to the project.

### 4.3 Acceptance Criteria

The completed system must demonstrate task creation, assignment, viewing, and status updates with persisted data, subject to the detailed acceptance criteria established in the approved SRS.
